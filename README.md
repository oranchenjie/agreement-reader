# 协议阅读器 · Agreement Reader

把没人愿意读的用户协议、隐私政策、服务条款，变成一份**能被核对**的说明书。

不只是"标出风险"，而是先**把协议讲明白**，再指出问题：

| 能力 | 说明 |
| --- | --- |
| **条款解读** | 逐条用大白话说明每个实质性条款在讲什么、对你意味着什么 —— 不只看风险 |
| **风险发现** | 分级标注不利条款，每条附原文引用、通俗解释、实际影响与建议 |
| **细节字眼** | 指出措辞上动过手脚的地方（"无需另行通知""视为接受""自行判断"…），并核验字眼确实来自原文 |
| **隐藏坑点** | 专门标记那些**一眼看不出来**的问题（需要结合别的条款、或藏在中性措辞后面） |
| **条款联系** | 指出"单看都没事、合起来才成立"的组合效应，并给出具体踩坑场景 |
| **协议问答** | 直接提问，回答严格基于协议原文，每条结论附原文出处并经过核验；协议里没写的就说没写 |
| **多份协议** | 可以把多份协议合并成同一个知识库一起提问 |

输入支持粘贴、网址抓取、PDF / Word / HTML / 上传文件、浏览器书签。
所有结论都标注原文出处，点击即可跳回原文核对。

## 快速开始

需要 **Node.js ≥ 20**（仅此而已，**零第三方依赖，无需 `npm install`**）。

### Windows：双击 `启动.cmd` 就行

**一个脚本搞定全部**：停掉旧服务 → 启动新服务 → 打开浏览器。会先问一句确认，回车即可。

```
==================================================
   协议阅读器 - 一键重启
==================================================

 按回车确认重启；输入 N 取消:

 [1/4] 停止已有服务 ...
        已结束 PID 12345
 [2/4] 等待端口释放 ...
 [3/4] 启动服务 ...
        使用: C:\Program Files\nodejs\node.exe
 [4/4] 等待服务就绪 ...

 启动成功！

 地址: http://127.0.0.1:8787
```

**优先用 Windows 原生 Node 运行，完全不经过 WSL** —— 地址永远是稳定的 `127.0.0.1`，
不受 WSL2 端口转发失效影响，浏览器里存的 API Key 也不会因来源变化而丢失。

同时它会**按端口结束所有旧实例**（Windows 侧 `netstat` + `taskkill`，WSL 侧 `pkill`），
所以「同时跑着两份服务、浏览器连到旧的那份」这种问题不会再发生。

| 脚本 | 用途 |
| --- | --- |
| `启动.cmd` | 一键重启（停止 + 启动 + 打开浏览器） |
| `停止.cmd` | 只停止 |
| `诊断.cmd` | 环境诊断（全英文输出，避免编码干扰排查） |

> **脚本编写约束**（都来自真实踩坑，有测试守着）：
> 行尾必须 CRLF（纯 LF 的 `.cmd` 在 cmd.exe 里会解析失败）；
> **命令行保持纯 ASCII**，中文只出现在 `echo` 里（中文要过 Windows ANSI 代码页，
> 放在 `start` 的窗口标题或路径参数里很容易崩）。

### 任何平台：命令行

```bash
./run.sh start     # 后台启动（关掉终端也不会停）
./run.sh status    # 查看状态
./run.sh stop      # 停止
./run.sh logs      # 实时看日志（Ctrl+C 退出，不影响服务）
./run.sh fg        # 前台运行（调试用，Ctrl+C 即停）
```

也可以用最朴素的方式：

```bash
node server.js
```

打开 <http://127.0.0.1:8787>，点右上角 **「模型设置」** 填入你的 DeepSeek API Key，就可以开始分析。

> 密钥**只保存在你自己的浏览器里**，每次分析时随请求发给本地服务使用，服务端不保存、不写日志、不回显。
> 清除浏览器数据即彻底消失。想完全离线跑（不调用模型）则在「分析方式」里选「仅本地规则」。

### 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 浏览器打不开 `127.0.0.1:8787` | 双击 `启动.cmd` 重启一次。仍不通就检查系统代理是否拦截了本地地址 |
| 页面功能像是旧的 / 提示"未知接口" | 说明连到了旧版服务。页面顶部会自动出现红色警告并写明处理办法；双击 `启动.cmd` 即可 |
| 提问后提示"服务版本过旧" | 同上 —— 双击 `启动.cmd` |
| 提示端口被占用 | `.env` 里改 `PORT`，或临时 `PORT=8899 ./run.sh start` |
| 提示 Node 版本过低 | 需要 ≥ 20，`node -v` 确认 |
| 页面能开但抓取什么都失败 | 检查本机网络；内网调试需 `ALLOW_PRIVATE_URLS=1` |
| 模型分析报 401 | 到「模型设置」里点「测试连接」确认密钥有效 |

### 也可以把密钥放在服务端

如果要部署成多人共用的服务，或不想在浏览器里存密钥：

```bash
cp .env.example .env
# 编辑 .env，填入 DEEPSEEK_API_KEY
node server.js
```

**优先级：请求里携带的密钥 > 服务端 `.env` 的密钥。** 两者都没有时，服务会自动降级为本地规则模式，并在结果里明确告知。

## 模型设置（网页内配置）

点右上角「模型设置」，或直接点状态灯：

| 项 | 说明 |
| --- | --- |
| **API Key** | 在 platform.deepseek.com 的 API Keys 页面创建 |
| **记住密钥** | 勾选 → 存 `localStorage`（关浏览器也在）；不勾 → 存 `sessionStorage`（关标签页即失效） |
| **API 地址** | 高级项。指向兼容 OpenAI 协议的自建/代理网关 |
| **逐条分析模型** | 调用量大，建议用快的（默认 `deepseek-v4-flash`） |
| **汇总模型** | 只调用一次，建议用更强的（默认 `deepseek-v4-pro`） |
| **测试连接** | 验证密钥可用性并列出可见模型，**不消耗生成额度** |

设计上的几个取舍：

- **服务端不保存密钥**。请求通过 `X-DeepSeek-Key` 头携带，只在单次请求的生命周期内存在于局部变量里。
- **绝不出现在响应或日志里**。所有返回前端的错误信息都过一遍脱敏（`sk-****`），测试里有专门断言。
- **测试连接只回显末四位**：既不泄露完整密钥，也能让用户确认填对了哪一把。
- **同源校验**：本地服务若不做防护，用户浏览器里任意恶意网页都能向 `127.0.0.1:<port>/api/...` 发请求（CSRF / DNS rebinding）。一旦涉及用户自带的 Key，这就不是理论风险，因此拒绝 `Origin` 与 `Host` 不一致的请求。

> ⚠️ 若把这个服务部署到公网，务必套 HTTPS —— 否则密钥会以明文经过网络。

## 配置

全部通过 `.env` 或环境变量，**环境变量优先**。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | **推荐留空**，改在网页里填。仅在需要服务端共用一把密钥时才设置 |
| `DSH_IGNORE_DOTENV` | `0` | 置 `1` 完全忽略 `.env`，只用真实环境变量（测试/CI 用） |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容网关地址，可指向自建/代理 |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | 逐条扫描用的模型（量大，建议用快的） |
| `DEEPSEEK_MODEL_SUMMARY` | 同 `DEEPSEEK_MODEL` | 最终汇总用的模型（建议用更强的） |
| `PORT` | `8787` | 服务端口 |
| `DSH_AGREEMENT_MOCK` | `0` | 置 `1` 完全离线，返回本地规则结果 |
| `ANALYZE_CONCURRENCY` | `3` | 分片并发数（上限 8） |
| `ANALYZE_CHUNK_CHARS` | `6000` | 单批字符预算，越小并发越多、单次上下文越短 |
| `DEEPSEEK_MAX_TOKENS` | `8192` | 逐条阶段的输出上限 |
| `DEEPSEEK_MAX_TOKENS_SUMMARY` | `16384` | 汇总阶段的输出上限（推理模型需要更大） |
| `DEEPSEEK_MAX_TOKENS_CEILING` | `65536` | 额度耗尽时自动加倍的上限 |
| `ASK_CONTEXT_MODE` | `auto` | `auto`（放得下就整篇送）/ `full` / `retrieve` |
| `ASK_WHOLE_DOC_CHARS` | `500000` | 整篇送检的字符上限，超过才退回检索 |
| `DEEPSEEK_THINKING` | `auto` | `auto` / `disabled` / `enabled`。推理模型把额度烧在思考上时可设 `disabled` |
| `DEEPSEEK_REASONING_EFFORT` | 空 | 思考强度，留空则不传 |
| `ANALYZE_MAX_TEXT_CHARS` | `400000` | 超长文本截断阈值 |
| `DEEPSEEK_TIMEOUT_MS` | `180000` | 单次模型请求超时 |
| `MAX_FETCH_BYTES` | `8388608` | 网址抓取体积上限（8MB） |
| `FETCH_TIMEOUT_MS` | `30000` | 网址抓取超时 |
| `ALLOW_PRIVATE_URLS` | `0` | 是否允许抓取内网/本机地址（防 SSRF，默认禁止） |
| `BROWSER_RENDER` | `1` | JS 渲染页面是否自动回退到本机无头浏览器 |
| `BROWSER_BIN` | 自动探测 | 手动指定 Chrome / Edge 可执行文件 |
| `BROWSER_TIMEOUT_MS` | `30000` | 无头渲染超时 |
| `MIN_USEFUL_CHARS` | `300` | 正文少于该字数视为抓取不完整 |

## 支持的输入形式

所有入口最终都收敛成同一份「规范文本」，下游完全无感。

| 形式 | 说明 |
| --- | --- |
| **粘贴文本** | 从网页直接复制的富文本会自动清理空白与噪声 |
| **划词分析** | 在页面任意位置选中 ≥150 字，会浮出「分析选中的 N 字」按钮 |
| **网址抓取** | 服务端抓取后剥离导航、页脚、Cookie 横幅、侧栏、广告、评论区；**JS 渲染页面会自动回退到本机浏览器渲染** |
| **PDF** | 纯 JS 解析：FlateDecode / LZW / ASCIIHex / ASCII85 / RunLength、过滤器链、对象流、xref 流与增量更新、ZIP64、ToUnicode（含中文 Identity-H 双字节）、内嵌 CMap、Differences、表单 XObject |
| **DOCX** | 直接读 ZIP 内的 `word/document.xml`，保留段落与列表项 |
| **HTML / MHT** | 同样走正文提取链路 |
| **TXT / MD / JSON** | JSON 会递归抽取其中的长文本字段 |
| **多文件** | 支持一次选多个文件，按顺序拼接 |
| **拖放** | 文件拖到页面任意位置即可 |

**编码处理**：自动识别 BOM、`Content-Type`、`<meta charset>`，并支持 **GBK / GB2312 / GB18030 / Big5**——中文站点协议用错编码会得到满屏乱码，这里做了专门处理。

## 协议问答（严格基于协议）

切换到结果页的「提问」标签，直接问，比如：

- 我的内容会被平台永久使用吗？
- 账号被封了余额能退吗？
- 会不会自动扣费？怎么取消？
- 数据会共享给哪些人？

### 为什么它不会胡编乱造

「问 AI 协议写了什么」最大的问题是**它会一本正经地编**。这里用了三层约束：

1. **上下文层：默认把协议整篇交给模型，不做筛选。**
   模型上下文足够大（这些模型是 100 万 token），一份协议通常才几万字，完全放得下。
   **判断权归模型，不归检索。**

   只有在语料真的超出上限时（默认 50 万字）才退回检索，
   而且**退回检索后也绝不空手拒答**：检索没命中，就把能装下的部分照样送给模型，
   并明确告诉用户"只送了前 N 个条款，答案可能在未送检的部分"。
   检索本身分严格 / 宽松两档，还带一层**口语同义词扩展**。

   > 这一层是踩坑改出来的：最初的实现是「先检索、检索不到就答没找到」，
   > 看似省 token，实际上把判断权交给了字面匹配 ——
   > 用户问「付了钱能退吗」而协议写「不予退还」，一个词都对不上，
   > 系统就会错误地宣布协议里没写。**省下的那点 token 是用户在付，
   > 不该由程序替他省。**
2. **提示层**：明确要求「协议里没写就说没写」，禁止用「通常」「大多数平台」填补空白；
   但**允许用通用知识解释术语**（如"仲裁是什么"），只要与协议内容分开陈述、不混为一谈。
3. **核验层（关键）**：模型给出的每条依据都要在原文里定位。
   **如果一条都对不上，无论模型说得多肯定，一律改判为「协议中未找到依据」**，
   并明确告诉用户"该结论无法在原文中核验，已不展示"。

第三层是这套机制和"直接问 AI"的本质区别：**模型可以声称有依据，但无法伪造依据。**

> 三档检索是实测踩出来的：最初实现里「检索不到就不调用模型」看似省钱，
> 结果把所有口语化提问都挡在门外，用户看到的永远是「协议里没写」。
> 现在的原则是：**判断权交给模型，检索只负责把料送到它面前。**

模型给出的 `clauseId` 写错时，还会用引文反查归位；真假混杂时只保留能核验的那部分。

### 多份协议一起问

点「知识库」可以勾选多份协议（当前的 + 历史记录里的）合并成同一个语料库一起提问。
每条依据都会标明来自哪一份协议。

### 联网搜索（可选）

勾选后会先做一次联网搜索，把结果作为**外部信息**一起给模型，回答里会单独标注
"以下来自网络，非协议内容"，并附上来源链接。搜索失败或被关闭不影响协议问答，
只是少一个信息源。这个功能默认可用，服务端可用 `WEB_SEARCH=0` 关掉。

### 离线模式

没有配置 API Key 时，问答会退化为**原文摘录模式**：只把检索到的最相关原文段落原样列出，
不做生成、不做推理。它不会编造 —— 因为它根本没有生成能力。

## 细节字眼与隐藏坑点

这两项是本产品的重点。

**细节字眼**：像「无需另行通知」「视为接受」「自行判断」「包括但不限于」「按现状提供」
「永久、不可撤销、免费、可转授权」这类措辞，单独看都不起眼，但往往是权利义务被转移的地方。
程序会把这些字眼单独列出来，**并且核验它确实逐字出现在原文中**（模型编造的字眼会被丢弃）。
提示词里同时明确写着：出现这些词**不等于**就是坑，必须结合上下文判断 ——
否则会退化成"见到『可能』就报风险"的噪声机器。

**隐藏坑点**：有些问题不是从字面能看出来的，比如

- 需要结合另一条才能理解危害（"收集设备信息" + "可与关联方共享" + "关联方含合作伙伴"）
- 藏在看起来中性的措辞后面
- 后果不在本条文字里体现，而在配套条款或实际执行中

这类会被标上「不明显」标记，可以在风险清单里用「只看不明显的」筛出来。

**条款联系**：有些坑是几条组合起来才成立的，单独看每条都正常。例如：

- 内容授权（永久不可撤销）+ 账号终止（随时封禁）→ 被踢出后内容依然被永久授权
- 单方变更 + 免责条款 → 规则随时可变，而改变带来的后果由你承担
- 数据共享 + 跨设备追踪 → 一套完整的用户画像与商业化链条
- 数据保留 + 账号终止 → 一边给你删除权，一边保留数据，实际架空了删除权

每一条都会给出「单独看是什么样 → 合起来变成什么样」以及一个具体踩坑场景。

## 部署到 GitHub Pages（免费，不需要域名）

这是一个**纯前端就能跑**的工具 —— 分析和问答逻辑全在浏览器里，只有调用 DeepSeek API 时需要网络。
所以可以直接托管在 GitHub Pages 上，**不需要买服务器、不需要买域名**。

### 三步搞定

```bash
# 1) 推到 GitHub（仓库名随意，比如 agreement-reader）
git add -A
git commit -m "feat: 协议阅读器"
git branch -M main
git remote add origin https://github.com/<你的用户名>/agreement-reader.git
git push -u origin main
```

2) 打开仓库 **Settings → Pages**，把 **Source** 设为 **GitHub Actions**

3) 回到 **Actions** 标签，等 "Deploy to GitHub Pages" 跑完

访问地址就是：

```
https://<你的用户名>.github.io/agreement-reader/
```

之后每次 `git push` 都会自动重新部署。

### 部署踩坑记录

**workflow 里刻意没有用 `actions/configure-pages`，请不要加回来。**
它唯一的产出是 `base_path`，而 `base_path` 就等于 `/<仓库名>`，
用 `github.event.repository.name` 一行就能算出来；但在「Pages 站点尚未建立」时
它会直接以 `Get Pages site failed ... Not Found` 失败，把整个部署卡死
（测试、构建、可达性检查全过之后才卡在这一步，非常难查）。
`upload-pages-artifact` 和 `deploy-pages` 都不依赖它。
`test/workflow.test.js` 会拦住它被重新引进来。

**构建产物是路径无关的。** 前端一律用**相对路径**引用 `src/`，
所以挂在站点根（本机服务端、自定义域名）或挂在子路径（项目站点 `/<仓库名>/`）
都能解析。改前端引用时请保持相对 —— 任何 `/xxx` 形式的引用在子路径下都会 404。

**如果 `git push` 一直卡住或超时**：多半是 `github.com:443` 被网络阻断了。
这种情况通常 `api.github.com` 还是通的，于是表现为「能查仓库、就是推不上去」。
改用 SSH 可以绕过（GitHub 的 `ssh.github.com:443` 和 `github.com:22` 一般不受影响）：

```bash
git push git@github.com:<你的用户名>/agreement-reader.git main
```

### 本地先验证一遍

```bash
npm run build:static      # 构建到 _site/
npm run preview:static    # 本地预览（刻意不带任何后端接口）
npm run check:static      # 检查产物里有没有 404
```

`preview:static` **不提供任何 `/api` 接口** —— 这样前端会探测不到后端，
自动切到纯静态模式，与 GitHub Pages 上的真实行为完全一致。

### 纯静态模式下哪些能用、哪些不能

| 能力 | 纯静态 | 说明 |
| --- | --- | --- |
| 粘贴文本分析 | ✅ | 核心功能 |
| 风险条款 / 条款解读 / 条款联系 | ✅ | 全部分析逻辑都在浏览器里 |
| 细节字眼 / 隐藏坑点 | ✅ | |
| 协议问答（含多份协议） | ✅ | |
| 上传 PDF / Word / HTML / 文本 | ✅ | PDF/Word 靠自研的纯 JS 解码器（`browser-shim.js`） |
| 抓取网页 | ❌ | 浏览器同源策略不允许读取其它站点 —— 请粘贴文本 |
| 联网搜索 | ❌ | 同上 |
| 抓取书签 | ❌ | 它需要一个本地服务来接收推送 |

不可用的功能会在界面上**明确标注**，不会让你点了才发现。

> 需要完整功能就在本机跑服务端版本：`node server.js`（见上面的快速开始）。
> 两种模式共用**同一份前端代码与同一份分析逻辑**，只是数据来源不同。

### 静态模式的隐私性反而更好

```
服务端模式：浏览器 → 本地服务 → DeepSeek
纯静态模式：浏览器 ────────────→ DeepSeek      ← 中间没有任何服务器
```

纯静态模式下**没有任何中间服务器**：协议文本和你的 API Key 直接由浏览器发往 DeepSeek。
没有后端可以记录、留存或泄露它们。

## 网址抓取：为什么有的网页抓不到

协议页抓取失败通常不是网络问题，而是下面三种情况。这三种都已经做了处理：

### 1. 网址没写 `https://`（最常见）

直接粘 `www.example.com/terms` 完全可以，会自动补全协议头。从中文文档里复制来的全角冒号 `：`、全角斜杠 `／`、零宽字符、夹杂的空格也都会自动清理。

### 2. 页面正文由 JavaScript 渲染

现在大量网站（尤其国内的隐私政策页）是前端渲染的 SPA，静态 HTML 里只有 `<div id="app"></div>`，正文全靠 JS 拉取。比如：

```
https://www.bilibili.com/blackboard/privacy-pc.html   →  整份 HTML 只有 8 个中文字符
```

这种情况**任何 HTML 解析算法都无能为力**，唯一通用的解法是真正执行一次 JS。所以这里会自动回退到**本机已安装的 Chrome / Edge 做无头渲染**：

```
静态抓取 → 判断是否空壳 → 用浏览器渲染 → 重新提取 → 合并结果
```

- 自动探测 Chrome / Edge（Windows、WSL、Linux、macOS 的常见安装位置 + `PATH`）
- 找不到浏览器就静默跳过，退回静态路径，**绝不因此报错**
- 可用 `BROWSER_RENDER=0` 关闭，或用 `BROWSER_BIN` 指定路径
- 渲染超时（默认 30 秒）或失败都会给出明确提示，并保留静态结果

> WSL 下如果 Chrome 位于 Windows 侧，路径形如 `/mnt/c/Program Files/Google/Chrome/Application/chrome.exe`，
> 会自动转换用户目录为 Windows 路径。若你的沙箱环境禁止跨工作区执行，会看到 `EACCES` 提示，此时手动粘贴即可。

### 3. 需要登录 / 有反爬限制

会返回明确的状态说明（403、401、429、超时、DNS 失败、证书错误都有各自的中文提示），并给出替代方案。

### 4. 用「抓取书签」—— 最稳的方式

上面三种手段都有天花板。真正一劳永逸的办法是**让你自己的浏览器去取**：

页面里展开「抓不到？用『抓取书签』从你自己的浏览器里取」，把那个按钮拖到书签栏。
之后在任何协议页面上点一下这个书签，内容就会自动出现在应用里。

为什么它几乎不会失败：

| 难点 | 为什么书签不受影响 |
| --- | --- |
| JS 渲染的 SPA | 用的是 `document.body.innerText`，即**渲染后**的可见文本 |
| 需要登录 | 用的是**你已登录的会话** |
| 反爬 / 风控 | 请求从你的浏览器、你的 IP、你的指纹发出，与正常浏览无异 |
| 懒加载 | 浏览器已渲染的部分直接取到 |

实现细节：书签以 `mode: 'no-cors'` + `Content-Type: text/plain` 发送（构成「简单请求」，不触发 CORS 预检）。
另外服务端对 `/api/ingest` 返回了 `Access-Control-Allow-Private-Network: true`——Chrome 的
Private Network Access 策略会对「公网页面 → 本机地址」的请求发起预检，不显式允许就会被浏览器直接拦掉。

书签脚本用 `String.raw` 生成，并且在测试里做语法校验：它本质是「以字符串形式嵌进 URL 的 JS」，
一旦转义出错，用户点下去只会**静默失败**（连报错都没有），极难排查。这个坑真实踩过一次。
`/api/ingest` 是**唯一豁免同源校验**的接口——它必须能接受来自任意站点的请求。为此做了严格限制：

- 只做一件事：把文本存进一个内存槽位
- **必须由用户在界面上手动点「载入」才会使用**，不会自动分析
- 不读取任何数据、不接触 API Key、不落盘
- 其它所有接口（`/api/analyze`、`/api/fetch-url`、`/api/verify-key`）**仍然拒绝跨源请求**，有测试专门守着这条边界

### 抓不到时的界面行为

失败**不会**只弹一个几秒后消失的提示（那样会让人以为"点了没反应"）。而是给一个常驻面板，分三种状态：

| 状态 | 表现 |
| --- | --- |
| **成功** | 绿色，显示字数；可一键查看并编辑文本 |
| **部分成功** | 黄色，显示"只抓到一部分内容"；仍可查看核对，也提示如何拿全 |
| **失败** | 红色，列出具体原因 + 三个明确出口：手动粘贴 / 用浏览器渲染 / 上传文件 |

最后一条永远是**手动粘贴**，因为那是最可靠的方式：在浏览器里打开页面 → `Ctrl+A` → `Ctrl+C` → 粘贴进来，拿到的是浏览器渲染后的完整正文。

## 工作原理

```
归一化 → 条款切分 → 本地规则预扫描 → 分片并发 MAP → 引文核验 → REDUCE 汇总 → 风险分校准
```

| 阶段 | 做什么 | 为什么这么做 |
| --- | --- | --- |
| **归一化** | 统一换行/空白/编码，去零宽字符、还原英文断词、剔除页码行 | 让后面所有字符偏移可信 |
| **条款切分** | 识别 `第十二条` / `3.2` / `(a)` / `Section 4` / Markdown 标题；识别不出就按段落聚合 | **纯规则、零成本、可复现**，并给每个条款稳定 id 与字符偏移 |
| **规则预扫描** | 27 类风险关键词本地匹配 | 作为线索喂给模型提升召回；也是模型不可用时的降级结果 |
| **MAP** | 按字符预算分片，多片并发，逐条输出结构化风险条目 | 单次长提示在长协议上召回明显更差 |
| **引文核验** | 逐条确认引文真实存在于原文并算出精确区间；对不上就**丢弃** | 这是「模型不能编造条款」的最后一道防线 |
| **REDUCE** | 汇总为风险分、结论、重点、分布、建议 | 需要全局视角，与逐条扫描分开 |
| **风险分校准** | 模型给分与条款加权分差距 > 40 时向本地分靠拢 | 防止「10 条严重条款却给 5 分」这类失真 |

### 三个让它「可核对」的设计

1. **强制引文**：提示词要求每条结论给出逐字原文片段，且由本地核验，编造的条目进不了报告。
2. **双向定位**：点结论 → 原文高亮滚动到视野；点高亮 → 清单选中对应结论。
3. **诚实标注**：本地规则模式、失败批次、被丢弃的条目都会写在报告的「请注意」里。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health?check=1` | 服务与 API Key 连通性自检 |
| `GET` | `/api/config` | 模型、限额、分类体系（前端单一来源） |
| `POST` | `/api/extract` | 提取文本。**请求体放原始字节**，文件名放 `X-Filename` 头 |
| `POST` | `/api/fetch-url` | `{ url }` → 抓取并提取正文 |
| `POST` | `/api/verify-key` | 验证凭据可用性并返回可见模型列表（不消耗额度） |
| `POST` | `/api/analyze` | `{ text, title?, mode? }` → 一次性返回完整结果 |
| `POST` | `/api/analyze/stream` | 同上，但以 SSE 推送各阶段进度 |

请求可携带以下可选请求头覆盖服务端配置（也可放在 JSON 请求体里，字段名相同）：

| 请求头 | 对应配置 |
| --- | --- |
| `X-DeepSeek-Key` | API Key |
| `X-DeepSeek-Base-Url` | API 地址 |
| `X-DeepSeek-Model` | 逐条分析模型 |
| `X-DeepSeek-Model-Summary` | 汇总模型 |

`mode` 可取 `auto`（默认，有密钥用模型否则降级）/ `llm`（无密钥直接报错）/ `heuristic`（强制本地规则）。

> `/api/extract` 用原始字节而不是 multipart，是为了避免手写 multipart 解析；前端也只需一次 `fetch`。
> 所有 `/api/*` 都会校验 `Origin` 与 `Host` 是否一致，不一致直接 403。

`mode` 可取 `auto`（默认）/ `llm` / `heuristic`。

## 模型调用的容错设计

接真实模型时会遇到一些"看起来像 bug、其实是额度语义"的问题，这里都做了处理。

### 推理模型的 max_tokens 会把思考过程算进去

**现象**：`模型未产出正文（finish_reason=length，思考过程已占用 20920 字）`

**原因**：`max_tokens` **同时覆盖思考过程（`reasoning_content`）与正文**。
推理模型（reasoner / pro 类）在额度不足时会把预算全烧在思考上，
于是正文一个字都没产出、`finish_reason` 却是 `length`。

**关键点：一味加倍 `max_tokens` 是治不好的** —— 实测中把上限从 8192 一路提到 32768，
思考量也跟着涨到 45724 字，永远追不上。正确的做法是**把思考关掉**：

```js
thinking: { type: 'disabled' }     // 或 reasoning_effort: 'low'
```

**处理（按优先级）**：

1. **先关思考**：检测到「空正文 + length + 有思考过程」就自动改用关闭思考重试一次。
   逐条分析本质是**结构化抽取**，并不需要深度推理，关掉思考反而更快更稳。
2. **再考虑加倍额度**：如果关思考没解决问题，才逐级提高 `max_tokens`。
3. **网关不支持时自动退回**：有些 OpenAI 兼容网关不认识 `thinking` 参数会直接 400，
   此时会识别出来、去掉该参数并退回第 2 条路径，不会让整次分析失败。
4. 彻底失败时的错误信息会**点名是哪个模型**并给出处置建议。

也可以手动强制：`DEEPSEEK_THINKING=disabled`（见 `.env.example`）。

> 如果你在用 `deepseek-v4-pro` 这类推理模型跑逐条分析，最省事的做法是
> **在「模型设置」里把「逐条分析模型」换成 `deepseek-v4-flash`** ——
> 逐条抽取不需要深度推理，换掉之后额度全留给正文，速度也快得多。

### 汇总失败时的多级降级

原来的行为是：汇总模型失败 → 直接用本地关键词统计生成报告。
问题是**本地统计会丢掉所有模型生成的解释与建议**，报告质量断崖式下降。

现在改成三级：

```
汇总模型 → 逐条模型（降级） → 本地统计
```

只有前两级都失败才退化为本地统计，并且会**明确告知用户发生了什么**。

### 其它已有的容错

- 逐条阶段按字符预算分片并发，**单个分片失败不影响整体**，只记警告
- 引用对不上原文的结论会被丢弃（防止模型编造条款）
- 模型给的风险分与条款加权分差距 > 40 时自动校准
- 请求失败按 429/5xx 退避重试，输出被截断时抢救完整条目

## 安全与隐私

- **API Key 默认只存在用户浏览器里**，随请求头发给本地服务，服务端不保存、不写日志、不回显。
  所有返回前端的错误信息都经过脱敏（`sk-****`），并有测试断言密钥不会出现在响应体与服务端日志中。
- **所有 `/api/*` 做同源校验**（`Origin` 必须与 `Host` 一致），阻止其它网页对本地服务发起 CSRF / DNS rebinding 请求。
- **默认禁止抓取内网/本机地址**（防 SSRF），需要本地联调时设 `ALLOW_PRIVATE_URLS=1`。
- **静态服务做了目录穿越防护**。
- **历史记录只存在浏览器的 localStorage**，服务端不落库、不写文件。
- 使用模型分析时，协议片段会发送到所配置的 API；选「仅本地规则」则**完全不外发**。
- ⚠️ 部署到公网时必须套 HTTPS，否则密钥会以明文经过网络。

## 已知限制

- **本地规则模式的准确率明显低于模型分析**，只适合快速筛查或离线演示；结果里会明确标注。
- **不解析 CSS 渲染语义**：靠 `display:none` 且类名无提示的隐藏样板可能残留。
- **扫描件 PDF 无法提取**（没有文本层），会给出明确提示，需改用 OCR 或粘贴。
- **约 3% 的 PDF 提取结果不可读**：使用 Adobe-GB1 等 CID 集合且完全没有 `/ToUnicode` 映射的字体（xeCJK / CTeX 导出常见），字形程序是无 Unicode 名称的 CID-keyed CFF，纯 JS 无法还原映射。此类文件会降级并给出「字体缺少 ToUnicode 映射」警告，而不是产出乱码。
- **旧版 `.doc`（二进制）不支持**，请另存为 `.docx`。
- **动态渲染页面**（正文由 JS 生成）抓不到内容，会提示改用粘贴。
- 风险分析**不构成法律意见**，涉及重大权益请咨询律师。

### PDF 解析器的真实验证

除 41 个构造用例（中文 ToUnicode 往返、各类 Filter、Predictor、对象流、加密与损坏文件降级）外，还在本机 **237 个真实 PDF**（讲义、培养方案、扫描件、书籍、证书）上做过全量回归：

```
total=237  ok=223  empty=14  threw=0  elapsed=12.1s
```

无二进制垃圾、无超时（最慢 < 1.5s），提取 66 万中文字符 + 196 万 ASCII 字符。14 个空结果全部是**正确诊断**（12 个纯扫描件、2 个加密文件）。这轮真实语料还暴露并修掉了两个构造测试发现不了的 bug：间接引用 `3 0 R` 被拆成三个记号、PNG 预测器的分支歧义导致 xref 流只解出 2 个条目。

## 从网页 Demo 到桌面 / APP

当前实现刻意把「纯逻辑」与「运行时」分开，为后续演进留了口子：

| 现在 | 后续 |
| --- | --- |
| `src/analyze/*`、`src/extract/*`、`src/normalize.js`、`src/segment.js` | **可直接复用**，不依赖 HTTP |
| `server.js` 的路由 | 换成 Tauri sidecar / Electron 主进程的本地接口 |
| 直连 DeepSeek API | 可替换为 DSH Python SDK（`DeepSeekHarness`），只需替换 `src/analyze/client.js` |
| 前端原生 ES Module | 可平移到 Tauri WebView，无需重写 |
| 网址抓取 | 移动端改为「分享链接」「分享截图」入口 |

要新增输入形式，只需在 `src/extract/index.js` 里加一条格式判定与一个解析分支；要新增风险类别，只需在 `src/analyze/taxonomy.js` 里加一条（提示词会自动带上，前端标签也会自动下发）。
