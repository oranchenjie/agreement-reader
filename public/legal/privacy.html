一句话总结：本工具不收集、不上传、不存储你的任何数据。

协议阅读器（Agreement Reader）可以部署成纯静态网页（例如 GitHub Pages），也可以在你的电脑上以本地程序方式运行。两种形态下，开发者都不运营任何服务器，也没有任何接收你数据的后端。下面逐项说明数据的具体去向。

一、两种运行形态（决定了数据流向）

本工具有两种使用方式，数据流向不同，请先确认你在用哪一种：

  • 纯静态模式（部署在 GitHub Pages 等静态托管上）：完全没有服务端。协议文本与你的 API Key 由浏览器直接发往你配置的模型接口，中间不经过任何服务器。
  • 本机服务端模式（在自己电脑上运行 node server.js）：由本机进程转发请求。该进程由你自己运行、受你自己控制，不向任何第三方回传数据，也不持久化你的密钥与协议内容。

无论哪种形态，开发者都不运营任何服务器，也没有任何接收你数据的后端。

二、API Key 的完整生命周期

  • 存放在哪：密钥只保存在你自己的浏览器里。勾选「记住密钥」时存入 localStorage，未勾选时存入 sessionStorage（关闭标签页即消失）。
  • 怎么被使用：每次发起分析时，浏览器把密钥放进 HTTP 请求头，直接发往你配置的模型接口（默认 api.deepseek.com）。纯静态模式下中间没有任何服务器；本机服务端模式下则由你本机的进程转发一次。
  • 服务端如何处理：本机服务端模式下，密钥仅在该次请求内用于调用模型 API，不保存、不写日志、不回显，请求结束后即从内存中释放。纯静态模式下密钥从不离开你的浏览器（除了发给模型接口本身）。
  • 怎么删除：在设置面板点击「清除密钥」，或清除浏览器数据（含 localStorage / sessionStorage），密钥即彻底消失。删除项目目录也会一并移除程序本身。
  • 提醒：密钥是你自己的账号凭证，请勿分享给他人；调用产生的费用由你自行承担。

三、协议文本去哪了

你提交的协议正文离开浏览器后，只有两个可能去处：

  • 模型分析模式：切分后的协议片段会从本机服务发送到你自己配置的模型 API 地址（默认 https://api.deepseek.com，可在设置中改为自建或代理网关）。这是完成分析所必需的，除此之外不会发送给任何其他方；这些片段如何被该第三方处理，取决于该第三方的政策。
  • 仅本地规则模式：使用关键词与规则匹配完成分析，完全不外发，也不消耗任何 API 费用，代价是准确率明显较低。

无论哪种模式，本机服务都不会把协议文本写入文件或数据库。

四、历史记录存在哪

分析结果、风险条目与历史记录只存在于你浏览器的 localStorage。服务端不落库、不写文件、不做备份。你可以在界面上逐条删除，或使用「清空」功能一键清除全部历史；清除浏览器数据同样会将其移除。存储空间用尽时，程序可能自动丢弃较早的记录。

五、日志说明

本机服务在控制台只输出极简的访问日志，格式为 方法 + 路径 + 状态码 + 耗时（例如 POST /api/analyze → 200 (1234ms)）。

  • 不记录请求体，因此协议正文不会进入日志；
  • 不记录密钥，也不会记录其他请求头；
  • 不记录 IP、浏览器指纹或任何可识别你身份的信息；
  • 日志仅打印在你自己的终端中，不会上传到任何地方；关闭程序后如需清理，可直接删除日志文件。

六、联网搜索会发送什么

联网搜索默认关闭，需你主动开启。开启后，本工具会把你的问题文本（为检索所需，可能包含协议中的少量关键词或片段）发送至第三方搜索引擎，并展示其返回的公开信息。搜索结果来自第三方，未经核实，与本工具无关。关闭该功能后，不会有任何内容发往搜索引擎。

七、如何彻底清除所有痕迹

  • 清除浏览器数据：清空该站点的 localStorage 与 sessionStorage，即可删除密钥、历史记录与全部设置；
  • 点击界面上的「清空」与「清除密钥」：分别删除历史记录与密钥；
  • 删除项目目录：移除程序本体、配置与终端日志；
  • 浏览器书签小工具：只是你手动添加的一个书签，删除该书签即可，不留其他痕迹。

八、部署到公网或多人环境时的提醒

本工具默认设计为仅在你自己电脑上、由你一个人使用：它监听本机端口，没有账号体系，也没有访问控制。如果你把它部署到公网、局域网共享主机或多人共用的机器上，必须自行添加 HTTPS 与访问控制（例如反向代理鉴权、网络隔离、防火墙规则），并自行评估由此产生的数据暴露风险。因自行改变部署方式而导致的任何后果，由部署者承担。
